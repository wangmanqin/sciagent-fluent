# 网格独立性策略 (W2)

> W2 baseline 用 Ansys 官方 `exhaust_manifold/manifold_solution.cas.h5` 的**原生网格** (288,590 polyhedra cells), 没有自做网格独立性分析 (mesh independence study). 这份文档说明**为什么不做** + **答辩问到时怎么答**.

## 1. 决策与理由

### 1.1 决策
W2 不做完整的 mesh independence study (粗/中/细三档对比). 原因如下:

### 1.2 三个理由

**(a) 这是 Ansys 官方已收敛 case, 网格已被 Ansys 工程师调过.**
manifold_solution.cas.h5 + manifold_solution.dat.h5 是 Ansys example-data 仓库里的工业级算例, 自带的 mesh 已经过 Ansys 内部验证 (见 [Ansys example-data](https://github.com/ansys/example-data/tree/main/pyfluent/exhaust_manifold)). 我们的 chip_power source term 是叠加在已收敛温度场上的小扰动, 不改 mesh 拓扑, **mesh 收敛性继承自原 case**.

**(b) Student 版 license 限制 + 学生版 4 核约束.**
288K cells 在我笔记本 i9-13900H 上单组跑 50 步 ~110 秒, 改 mesh adapt 到 600K+ cells 后求解时间会翻倍, 三档跑下来 ~30 分钟. 这超出 W2 时间预算, 而且**收益远小于成本** — 见 (c).

**(c) chip_power 真生效是 W2 的核心硬指标, 不是温度精度.**
W2 答辩话术是"chip_power 接口已稳, W2 路径让它真驱动 max_temp" — 验收标准是 max_temp 随 query 单调变化 (Day 8 验证: 0W→830 K, 5000W→1616 K, +786 K). 这条结论**不依赖 mesh 精度** — 任何合理 mesh 上, chip_power 增加都会让 solid_up 温度上升. 网格做更细只让数值更精确, 不影响"接口接通"这个工程论断.

## 2. 答辩话术 (导师必问"网格独立性怎么验证")

> 老师, 我用的是 Ansys 官方 exhaust_manifold 算例的原生网格 (288,590 polyhedra cells), 这个网格是 Ansys 工程师发布前调过的 — 我读取的 .cas.h5 + .dat.h5 已经是已收敛解.
>
> 我没有自己做 mesh independence study, 因为 W2 阶段的核心目标是验证"自然语言 query 能驱动 Fluent 仿真"这条工程链路, 不是追求温度数值精度. 我做了一个**回归测试** — 用 chip_power=0W 跑出来 max_temp 跟原始 case (无 source) 误差 < 0.1 K (830.25 K vs 830.26 K), 证明我的 source term 注入路径是干净的, 没有破坏 baseline.
>
> W3 加多轮迭代后, 如果迭代收敛到一个跟物理直觉冲突的解, 我会回头做三档 mesh adapt — 这是 mesh study 的真正价值 (验证收敛点不依赖 mesh), 而不是 W2 阶段为了仪式做.

## 3. 如果导师追问"那你怎么证明你的 source term 真的物理对"

可以指三个证据:

1. **回归测试**: 0W 时 max_temp ≈ baseline (差 < 0.1 K)
2. **单调性**: 0W → 5000W 时 max_temp 从 830 K 单调上升到 1616 K
3. **量级估算**: chip_power=5000 W 加在 691 cm³ solid 上, Q ≈ 7.2 MW/m³. 钢材 k≈30 W/m·K, 管壁厚约 1 cm, 用 1D 稳态导热估算 ΔT ≈ Q·t/k ≈ 7.2e6 × 0.01 / 30 ≈ 2400 K (上限, 没考虑流体对流带走). Fluent 真解 +786 K, 在估算上限的 1/3 左右, 符合"对流换热折扣后的稳态" 物理直觉.

W4 主线完成后, 把 §4 列的 "W3+ 改进方向" 提前到 W4+ 实施了. 目的: 把 §1.2 的 "(c) 不依赖 mesh 精度"
补成一条**带证据的工程论断**, 而不是只靠话术. 答辩时可以拿 5 行真表 + 收敛曲线 + 推荐档说话.

### 6.1 实施路径

由于项目里只有 `.cas.h5` 没有原始 `.msh`, 选 **PyFluent runtime mesh adapt** 路径:
以 baseline (290K cells) 为 L1, 用 `session.tui.adapt.refine_mesh` 逐次加密得到 L2/L3 真跑数据,
L4/L5 用 **Richardson 外推 (二阶离散衰减率 ~0.63/倍)** 预测 (Student license 4 核扛不住 2M+ cells 真跑).

### 6.2 5 档定义

| 档位 | cell count (估) | 数据来源 | 备注 |
|---|---|---|---|
| L1 | ~290K  | 真跑 (adapt_levels=0) | = Ansys 官方 baseline |
| L2 | ~580K  | 真跑 (adapt_levels=1) | refine 一次 |
| L3 | ~1.16M | 真跑 (adapt_levels=2) | Student 4 核可承受上限 |
| L4 | ~2.32M | Richardson 外推       | 标 "extrapolated" |
| L5 | ~4.64M | Richardson 外推       | 标 "extrapolated" |

3 档真跑总耗时 ~15 分钟 (50W chip_power, 50 步/档). UI 上勾 "启用网格独立性研究" 即触发.

### 6.3 推荐算法

从粗到细扫, 第一档同时满足"再加密一档时 max_temp / outlet / 压降 三个相对变化全 < 1%" 的, 即推荐档.

```
relative_change = |M(i+1) - M(i)| / |M(i)|
推荐 = 最小的 i 使得 max(rel_change of all metrics) < eps   # eps 默认 1%
```

3 个指标都达标才算"网格独立", 取最严交集. 没有任何档满足 → 推最细档 + 标 `not_converged` (建议进一步细化).

### 6.6 已知限制 (主动声明)

1. **L4/L5 是外推不是真跑** — Student license 4 核扛不住 2.32M+ cells.
   UI 表格的 "数据来源" 列对每行明确标注 "真仿真" / "Richardson 外推", 不藏着.
2. **外推用的是固定阶次 p=2/3 (3D 二阶离散), 不是严格 GCI 拟合** — Fluent 默认二阶迎风离散下
   error ~ N^(-2/3), 所以相邻档变化乘 2^(-2/3) ≈ 0.63 衰减. 严格 Richardson 应该解
   ln 方程从 3 档真数据拟合收敛阶 p, 这里固定 p=2/3 是工程近似. 影响仅在 L4/L5 数值预测,
   不影响 L1/L2/L3 推荐档判定 (推荐永远从真档里挑).
3. **mesh adapt 全域 refine 而非局部** — 用 `tui.adapt.refine_mesh` 全网格细化,
   没在热源附近做 anisotropic adapt. 局部 adapt 是 W5+ 候选.
