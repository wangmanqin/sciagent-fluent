③ 五大架构决策（答辩 answer-script）

写在 设计思路.md §6，一切 PR / 重构都要对照这五条。

DECISION 1

LLM 只出 JSON

DeepSeek 永远不写 Python，只输出受限 schema。降低幻觉面，解耦 prompt 和 PyFluent API 变化。

DECISION 2

分层单位

用户层用 W、m/s（物理直觉）；Fluent 层用 W/m³、Pa（工程）。换算放 wrapper，不放 LLM。

DECISION 3

Baseline-first

用 Ansys 官方 conjugate-heat-transfer 教程做几何/网格基线，只换参数。W1-W4 完全不动 CAD。

DECISION 4

状态机 + 检查点

LangGraph 节点：intent → retrieve → setup → run → analyze → 迭代/输出。每节点持久化状态。

DECISION 5

每层都有 fallback

modern API 失败 → TUI；JSON 失败 → 重试；仿真发散 → 回滚。可靠性 > 性能。

④ 一句话的旅程（trace）

假设你输入："芯片 15 瓦，风速 2 米每秒，跑 200 步"

1
用户终端
python -m agents.intent_parser "芯片 15 瓦，风速 2 米每秒，跑 200 步"
2
parse_intent() 读 config.yaml，构造 OpenAI 兼容 client，向 DeepSeek 发 system prompt + user 消息。
response_format={"type": "json_object"} 强制 JSON 输出
3
DeepSeek 返回：
{"chip_power_watts": 15.0, "inlet_velocity_ms": 2.0, "max_iterations": 200}
4
SimulationParams(...) Pydantic 校验：类型对、范围对、没多余键。
失败 → 把错误塞回对话，让模型自我修正再试一次。
5
run_simulation(params)：launch_fluent → read_case → 应用速度 → hybrid initialize → iterate(200)
session.setup.boundary_conditions.velocity_inlet["cold-inlet"].momentum.velocity = 2.0
6
查询温度：通过 TUI /report/volume-integrals/maximum 写到临时文件，正则抠数字。
为什么用 TUI？API 在 0.20-0.38 之间签名变化频繁，TUI 20 年没变过。
7
analyzer hook (Day 5)：在 session.exit() 之前，run_simulation 调 result_analyzer.analyze(session, params, partial_result)。
→ 抓温度云图 PNG（modern API → TUI 双轨 fallback）
→ 拼中文报告：警戒线 85°C 判定，写 report.txt
→ 存 result.json 给 Day 6 LangGraph 下游用
reports/run_20260425_214235/{contour.png, report.txt, result.json}
8
finally 块：无论成败必 session.exit()。学生版 license 槽位极少，关不掉就一直占着。
9
返回完整 result dict（数字 + analyzer 加的字段）：
{"max_temp_K": 313.15, "outlet_avg_temp_K": 295.7, "within_spec": True, "margin_C": 45.0, "contour_image_path": ".../contour.png", "report_text_path": ".../report.txt", ...}
